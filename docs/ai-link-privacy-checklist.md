# AI連携 提出前プライバシーチェックリスト（S-10）

AI連携（S-01〜S-07）について、App Store のプライバシー申告で
「開発者が収集しない」形が維持できるかを、コードの実測に基づいて確認した記録。
確認日: 2026-11-05 / 対象: main（PR #18 マージ時点）＋ S-05 ブランチ

## 結論

AI連携によって **開発者が新たに収集するデータは無い**。スナップショットは
利用者本人が設定した送信先（利用者自身の Worker）にのみ送られ、開発者は
そのデータにアクセスできない。したがって AI連携は、既存のプライバシー申告へ
新たな収集項目を追加する理由にはならない。

## 根拠（コードで確認した事実）

- [x] アプリ内の `URLSession` 利用は2ファイルのみ
  - `ProductSearchService.swift`（JAN 商品検索。従来機能。送信先は開発者の商品検索 Worker で、クエリは JAN・キーワード）
  - `SnapshotLinkService.swift`（AI連携。送信先は利用者が設定した URL のみ。コード内に固定の送信先 URL は存在しない）
- [x] 解析・広告・トラッキング系 SDK の参照なし（Firebase / Amplitude / Mixpanel / Sentry / Crashlytics / AppsFlyer 等を全 Swift ソースで検索し該当なし）
- [x] サードパーティ Swift Package 依存なし（pbxproj に `repositoryURL` を持つリモートパッケージ参照なし）
- [x] AI連携のデフォルトは OFF。送信は利用者が URL とトークンを設定し、有効化した場合にのみ発生する
- [x] 書き込みトークンは Keychain のみに保存（UserDefaults・plist には保存しない）。読み取りトークンは端末に保存しない
- [x] 送信データはスキーマ v1 の範囲のみ（名称・JAN・数量・期限・保管場所メモ・更新日時）。位置情報・連絡先・端末識別子は含まない
- [x] `PrivacyInfo.xcprivacy`（リポジトリに同梱）の申告内容と矛盾しない
  - 収集データ: OtherUserContent（リンクあり・App機能・トラッキングなし）、SearchHistory（リンクなし・App機能・トラッキングなし）
  - アクセス API: UserDefaults（CA92.1）
  - AI連携のデータは「開発者が受け取る」のではなく利用者の指定先へ送られるため、この申告への追加は不要という整理
