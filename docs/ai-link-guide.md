# AI連携ガイド（Stockpile × あなたのAIアシスタント）

Stockpile の備蓄データを、**あなたが管理する送信先**を経由して、あなたのAIアシスタント
（Muse など）に読み取り専用で渡すためのガイドです。

- 連携はデフォルト OFF・無料です。有効にした人だけが使います
- データの送信先は、開発者のサーバーではなく **あなた自身の Cloudflare Worker** です
- AI 側は読み取り専用です。アプリのデータを変更したり、注文したりはしません
- 送信されるのは平文 JSON（アイテム名・JAN・数量・期限・保管場所）です。
  送信先は自分で管理する場所だけを設定してください

全体の流れ:

```
アプリ --PUT(書き込みトークン)--> あなたの Worker --GET(読み取りトークン)--> AI
```

## 1. 送信先 Worker を用意する

リポジトリの `templates/snapshot-worker/` が雛形です。Cloudflare のアカウントが必要です
（無料枠で十分です）。

公式 CLI `cf` を使う手順（動作確認済みの手順）:

```bash
# 1) ログイン（ブラウザが開きます）
cf auth login

# 2) KV 名前空間を作成（表示される id を控える）
#    ※ プロジェクトフォルダの外で実行してください
cf kv namespace create stockpile-snapshots

# 3) テンプレートを配置し、cloudflare.config.ts の KV id を
#    手順2の id に書き換える

# 4) トークンを2本発行する（読み取り用と書き込み用は必ず別々に）
openssl rand -hex 32   # 書き込み用
openssl rand -hex 32   # 読み取り用

# 5) シークレットファイルを用意してデプロイ
#    .secrets ファイルに WRITE_TOKEN=... / READ_TOKEN=... を書く（Git に入れない）
cf deploy --secrets-file .secrets
```

デプロイできたら疎通確認:

```bash
curl https://<あなたのWorker>/v1/health
# → {"ok":true}
```

送信先 URL は `https://<あなたのWorker>/v1/snapshot` です。

## 2. アプリ側の設定

1. アプリの「設定 → AI連携」を開き、「AI連携を使う」を ON
2. 送信先 URL に手順1の URL を入力
3. 書き込みトークンに、手順1で発行した **書き込み用** トークンを入力
   （この端末の Keychain にだけ保存されます）
4. 「今すぐ送信」を押して、成功表示を確認
5. バージョンによっては「自動送信」トグルがあります。ON にすると、
   アプリを開いた時と開いている間の変更が自動で送られます
   （バックグラウンドでの定期送信は iOS の制約のため行いません）

家族共有中の場合、共有メンバーの備蓄データも送信対象に含まれます。
送信は、有効化した端末からのみ行われます。

## 3. AI 側の設定

1. アプリの AI連携画面にある「Muse へのセットアップ依頼」文をコピーして、
   あなたの AI アシスタントに貼ります
2. AI の案内に従い、**読み取り用** トークンを安全な入力方法で渡します
   （チャット本文にトークンを貼らないでください）
3. 設定が終わったら、AI に「在庫を見せて」と聞いて、
   件数と生成日時（generatedAt）がアプリ側と一致するか確認します

## 4. トークンの失効・再発行

漏れた疑いがある場合や、AI へのアクセスを止めたい場合:

- **読み取りトークンの失効**: Worker のシークレット `READ_TOKEN` を新しい値に
  差し替えて再デプロイ（`cf deploy --secrets-file ...`）すると、古いトークンは
  即座に無効になります。AI 側には新しい読み取りトークンを渡し直してください
- **書き込みトークンの失効**: 同様に `WRITE_TOKEN` を差し替えて再デプロイし、
  アプリの AI連携画面で新しい書き込みトークンを入力し直してください
- 連携自体を止めるだけなら、アプリの「AI連携を使う」を OFF にすれば
  送信は止まります（Worker 側のデータは残ります。消したい場合は KV の
  `snapshot:current` を削除してください）

## 5. 困ったときの切り分け

| 症状 | 確認すること |
| --- | --- |
| 送信で「認証に失敗しました」 | アプリに入れたのが読み取り用でなく書き込み用か。Worker 側の `WRITE_TOKEN` と一致しているか |
| AI が「401」で読めない | AI 側の読み取りトークンが古い。再発行した場合は渡し直し |
| AI が「まだ届いていない（404）」と言う | アプリで「今すぐ送信」を実行したか。送信先 URL が `/v1/snapshot` で終わっているか |
| `health` も応答しない | Worker のデプロイ先 URL が正しいか。Cloudflare 側の障害情報 |
| 件数が合わない | アプリのファミリー切り替え状態（送信対象は現在のファミリーの範囲）。generatedAt がいつの情報か |

## 6. フォールバック（Worker が使えない場合）

Worker を経由しなくても、スナップショット JSON を直接 AI に渡せます:

```bash
curl -H "Authorization: Bearer <読み取りトークン>" https://<あなたのWorker>/v1/snapshot
```

取得した JSON を AI とのチャットに貼れば、その時点の内容について回答できます
（自動連携ではないため、鮮度は貼った時点のものになります）。

注意: アプリの「バックアップ書き出し」JSON は形式が異なるため、そのままでは
AI連携用スナップショットとして使えません。
